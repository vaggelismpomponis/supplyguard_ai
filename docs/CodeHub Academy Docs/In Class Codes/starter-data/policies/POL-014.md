# Incident and Outage Linking

When an open outage explains a reported symptom, the request is linked to the outage instead of opening a separate ticket or applying account changes.

Dependencies count: an outage on a service also affects all applications that depend on it, directly or transitively. Linking requires approval because it creates a ticket record.

## Rules

1. **POL-014-R01** When an open outage explains a reported symptom, the request is linked to the outage.
2. **POL-014-R02** A separate ticket is not opened for a symptom an open outage explains.
3. **POL-014-R03** Account changes are not applied for a symptom an open outage explains.
4. **POL-014-R04** Dependencies count: an outage on a service affects every application that depends on it.
5. **POL-014-R05** Dependencies are followed transitively, for example VPN to Identity Provider.
6. **POL-014-R06** Keyword matching alone is not sufficient to identify the cause.
7. **POL-014-R07** The outage must be open at the time of the request.
8. **POL-014-R08** Closed outages are mentioned only as history.
9. **POL-014-R09** The outage scope (office) must match the employee's office when the outage is office-specific.
10. **POL-014-R10** The symptom must be consistent with the outage symptoms description.
11. **POL-014-R11** Linking a request to an outage creates a ticket record and requires explicit approval.
12. **POL-014-R12** The assistant shows the outage ID and the latest update before asking for approval.
13. **POL-014-R13** Linked requests inherit the outage priority.
14. **POL-014-R14** Linked requests are closed automatically when the outage is resolved.
15. **POL-014-R15** The employee is informed about the outage and the expected next update.
16. **POL-014-R16** Other teams affected by the outage can be listed from the service dependency graph.
17. **POL-014-R17** Affected teams are determined through the applications they use.
18. **POL-014-R18** Employees without a known team are reported as such and not guessed.
19. **POL-014-R19** A new outage is declared by an engineer only.
20. **POL-014-R20** If more than 5 similar requests arrive without a known outage, escalate; see POL-016.
21. **POL-014-R21** After resolution, linked users are asked to retry before reopening a ticket.
22. **POL-014-R22** Outage notes are kept for 24 months.
23. **POL-014-R23** The response must cite this policy by document ID and effective date.
