# Ticket Priority and SLA

P1: business-critical or security incident, first response 30 minutes. P2: team impact, 2 hours. P3: single user, 1 working day. P4: requests, 3 working days.

Urgency stated by the employee (for example a Friday deadline) raises priority at most one level.

## Rules

1. **POL-015-R01** Priority P1 is business-critical or a security incident.
2. **POL-015-R02** P1 first response time is 30 minutes.
3. **POL-015-R03** Priority P2 is team-wide impact.
4. **POL-015-R04** P2 first response time is 2 hours.
5. **POL-015-R05** Priority P3 is single-user impact with a workaround.
6. **POL-015-R06** P3 first response time is 1 working day.
7. **POL-015-R07** Priority P4 is a request or question.
8. **POL-015-R08** P4 first response time is 3 working days.
9. **POL-015-R09** Urgency stated by the employee raises priority at most one level.
10. **POL-015-R10** Urgency can never raise a request above P2 unless it is a security incident.
11. **POL-015-R11** Deadlines are recorded in the ticket description.
12. **POL-015-R12** Requests linked to an outage inherit the outage priority.
13. **POL-015-R13** Security incidents are always P1.
14. **POL-015-R14** Lost devices are P1.
15. **POL-015-R15** Printer problems are P3 by default.
16. **POL-015-R16** Software requests are P4 by default.
17. **POL-015-R17** Password and unlock requests are P3 by default.
18. **POL-015-R18** Priority is set by the support engineer and can be changed with a reason.
19. **POL-015-R19** A priority change is recorded in the ticket history.
20. **POL-015-R20** Tickets are escalated when the response time is missed by 50%.
21. **POL-015-R21** Business hours are 08:00 to 18:00 local time on working days.
22. **POL-015-R22** P1 tickets are handled outside business hours by the on-duty engineer.
23. **POL-015-R23** The response must cite this policy by document ID and effective date.
