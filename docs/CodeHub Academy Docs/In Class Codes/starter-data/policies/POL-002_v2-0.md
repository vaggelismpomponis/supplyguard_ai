# Password Reset Policy

Replaces version 1.0. Where two versions exist, the version with the later effective date applies.

A credential reset changes an account and therefore requires explicit approval by the support engineer before execution. The employee identity must be verified (manager confirmation or MFA challenge).

A reset must NOT be proposed when an open outage on the Identity Provider explains the login symptom; link the request to the outage instead, because a reset will not fix a provider-side failure.

The temporary password is valid for 24 hours and is delivered through the verified mobile number only. Passwords must have at least 14 characters and expire every 180 days.

## Rules

1. **POL-002-v2.0-R01** Where two versions of this policy exist, the version with the later effective date applies; this version takes precedence over v1.0.
2. **POL-002-v2.0-R02** Every credential reset requires explicit approval by the support engineer before execution.
3. **POL-002-v2.0-R03** The assistant shows exactly what will be executed before asking for approval.
4. **POL-002-v2.0-R04** A rejected reset must never be executed.
5. **POL-002-v2.0-R05** An approved reset must be executed exactly once, even if the application restarts.
6. **POL-002-v2.0-R06** The employee identity must be verified before a reset is proposed.
7. **POL-002-v2.0-R07** Accepted verification methods are manager confirmation or a successful MFA challenge.
8. **POL-002-v2.0-R08** Verification by email address alone is not sufficient.
9. **POL-002-v2.0-R09** A reset must not be proposed when an open outage on the Identity Provider explains the login symptom.
10. **POL-002-v2.0-R10** In that case the request is linked to the outage instead.
11. **POL-002-v2.0-R11** The temporary password is valid for 24 hours.
12. **POL-002-v2.0-R12** The temporary password is delivered only through the verified mobile number.
13. **POL-002-v2.0-R13** The temporary password must never be sent by email or chat.
14. **POL-002-v2.0-R14** The employee must change the temporary password at the next sign-in.
15. **POL-002-v2.0-R15** New passwords must have at least 14 characters.
16. **POL-002-v2.0-R16** New passwords must contain upper case, lower case, a digit and a symbol.
17. **POL-002-v2.0-R17** Passwords expire every 180 days.
18. **POL-002-v2.0-R18** A new password may not equal any of the last 12 passwords.
19. **POL-002-v2.0-R19** A maximum of 3 resets per employee per 30 days is allowed; further requests are escalated.
20. **POL-002-v2.0-R20** Resets for shared accounts are not allowed; the account must be converted to individual accounts.
21. **POL-002-v2.0-R21** Service account credentials are rotated by the Systems Administrator, not by this process.
22. **POL-002-v2.0-R22** Applications with their own local credentials (for example the Client CRM) may be reset after verification.
23. **POL-002-v2.0-R23** Every reset is recorded in the ticketing table with approver and timestamp.
24. **POL-002-v2.0-R24** A suspected compromise (phishing, malware) is escalated instead of reset; see POL-010.
25. **POL-002-v2.0-R25** The response must cite this policy as POL-002 v2.0 with its effective date 2026-06-01.
